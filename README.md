# Discovery-9 MD-trajectory feature study

We ran 30 ns molecular-dynamics trajectories on the discovery-9 NewBench set (9 targets × 30
candidate ligands). Question: can cheap MD-derived features predict early enrichment (BEDROC α=20
— Truchon-Bayly early-enrichment metric) better than docking or MM-GBSA rescoring? Short answer:
no, not on n=9.

## NewBench-27 study scope

The full cohort is **NewBench-27** = **9 discovery** targets (MD + MM-GBSA already computed) +
**18 validation** targets (pre-registered in
`data/external/gbsa-study/data/raw/newbench_targets.csv` under `split == 'validation'`; MD +
MM-GBSA **not computed yet** — waiting on the next compute slot). Rough wallclock for the 18:
~540 productions × ~24 h GPU for MD, plus ~50 s/complex × 540 complexes × 48 combos for the
GBSA rescore. User decides when to schedule. The target list is version-controlled and frozen.
Once the 18 land, kinase n goes 2 → 10, protease n goes 4 → 5, and every other family (reader,
nuclear receptor, hydrolase, transporter, transferase, secreted protein, ion channel,
unclassified) reaches n ≥ 2 for the first time.

- **Discovery (9, computed).** `2XU3`, `3I06`, `4A5S`, `4L7G`, `4QB3`, `5HU9`, `8ELC`,
  `9D9I`, `9SI4`. Every headline number in this repo is on these 9.
- **Validation (18, queued — see compute note above).** By family:
  - Kinase (8): `4B6L`, `4X7Q`, `5OTE`, `6Z1T`, `8A27`, `8X92`, `9J9D`, `9Y9N`
  - Protease (1): `7D5B`
  - Reader (1): `6E1Z`
  - Nuclear receptor (1): `5HJS`
  - Ligand-gated ion channel (1): `9GJ1`
  - Hydrolase (1): `5M7U`
  - Electrochemical transporter (1): `8ZP2`
  - Secreted protein (1): `9OJO`

  (18 total. See `notebooks/01_scope_and_map.ipynb` for the full table + a status heatmap.)

## Headline result

Panel BEDROC α=20 for three rankers on the full 9-target panel (270 complexes). Per-target
BEDROC averaged across the panel; 95% CI from bootstrapping targets (B=5000). Canonical
values live in `data/derived/canonical_baselines.csv`.

| Ranker                                                     | Panel BEDROC α=20 | 95% CI          | n_targets |
|------------------------------------------------------------|-------------------|-----------------|-----------|
| Docking score (upstream pose seed)                         | **0.516**         | [0.30, 0.73]    | 9         |
| GBSA-locked combo `igb2_di4_salt0.15_st0.0072`             | **0.541**         | [0.36, 0.71]    | 9*        |
| Best single MD feature (`lig_buried_sasa_std_A2`, naive)   | **0.603**         | [0.39, 0.78]    | 9         |

All three sit on top of each other. Overlap is huge on n=9. Treat the ordering as a null.

*GBSA-locked has data for 8 of 9 targets — the 4A5S trajectories were never rescored upstream.
The **canonical** 9-target value **0.541** imputes 4A5S = 0 (worst case). The 8-target-subset
value where GBSA has data is 0.609 [0.48, 0.75]; use it only for head-to-head against another
scorer that also has no 4A5S data. Regenerated by `reproduce/canonical_baselines.py`.

## Verdict

- **Claim A (retained, scoped).** None of the ML pipelines beat GBSA. Ridge, RandomForest,
  ExtraTrees, HistGradientBoosting, ElasticNet, SVM-RBF, LogReg-L1/L2 — every one sits in
  GBSA's CI. Family stratification: proteases (n=4) — GBSA-locked panel BEDROC =
  **0.351 [0.121, 0.581]**; ML pipelines cluster at 0.31 ± 0.10 (range 0.15 ExtraTrees →
  0.44 ElasticNet). Every ML CI overlaps GBSA. Kinases (n=2) saturate near 0.82; three
  singleton families (bromodomain, chaperone, other) can't be stratified. With 9 targets we
  can only detect lifts of +0.11 BEDROC for the tightest pipelines (Ridge, RF) and +0.37 for
  the noisiest (SVM-RBF) at 80% power. Claim A holds for the two families with n ≥ 2.
- **Claim B (retracted).** The original headline was that `lig_buried_sasa_std_A2` beats GBSA
  at panel level — BEDROC 0.674 on the 8-target subset that silently dropped 4A5S. Doesn't
  hold on n=9. We put 4A5S back (labels recovered from the upstream metadata table) and the
  deployable LOTO K=1 rank-fusion collapses to panel BEDROC ≈ 0.32. Same feature on the naive
  9-target panel with 4A5S imputed at 0 scores 0.603 [0.39, 0.78] — a point-estimate delta of
  +0.062 over GBSA-locked 0.541 [0.36, 0.71], sitting well inside GBSA's CI. Every hardening
  condition (MW-residualised — MW regressed out per target, size-residualised, bound-only,
  PBC-clean) drops the feature below 0.51. Same story either way.[^noise-exclusion]

[^noise-exclusion]: Two columns — `lig_partial_q_sum` (in `ligand_chem.parquet`) and
    `ligand_partial_charge_sum` (in `features.parquet`) — are the SAME neutral-by-construction
    sum-of-partial-charges column (mean ~-1e-6, std ~1e-5, all 270 values essentially zero).
    They produced spurious BEDROC hits from floating-point roundoff and are now excluded from
    the naive ranking in `reproduce/canonical_baselines.py`. See `docs/GLOSSARY.md` §
    "noise columns (do not use)".
- **NB 27 MD → GBSA surrogate.** Three tiers, reported honestly:
  quasi-circular r ≈ 0.93 (feature set includes GBSA-energy inputs);
  partial-leak r ≈ 0.778 (MD stability retained);
  clean r ≈ 0.455 [0.236, 0.674] (ligand-chemistry descriptors only).
  The clean number is the deployable one. It's modest.

## How the 270 productions were configured

The MD `.mdp` used for the 270 discovery-9 productions is **not** hand-picked. It's the top-1
config from an Optuna Bayesian-optimisation study (`md_prod_v1`, 200 completed trials, plus
follow-up `md_prod_v2` that opened the envelope further). The search space is 17 parameters
covering GROMACS-2025 MDP + FF tier (`data/external/bayesopt/code/space_v2.py`). Force-field
family stays frozen at `ff14SB + gaff2 + tip3p + vdw_modifier=Potential_Shift` — BayesOpt trials
replay a pre-equilibrated seed topology (topology reused, no re-solvation), so swapping the FF
mid-flight isn't physically valid. Winner (trial 96, fitness 20.073): `integrator=md`, `dt=2 fs`,
`tcoupl=berendsen`, `pcoupl=C-rescale`, `constraints=h-bonds`, LINCS (linear constraint solver)
order=4, no HMR (hydrogen-mass repartitioning), no MTS (multiple-timestep integrator) — a
conservative envelope. Full provenance, DB queries, and figures in
`notebooks/02_md_config_provenance.ipynb`; source artifacts under `data/external/bayesopt/`.

## Repository structure

One flat notebook tree, organised as a 4-act narrative (`notebooks/00_…` through
`notebooks/30_…`, iter_05 flattening). Both the upstream GBSA-physics + GROMACS-DOE work (from
the `gbsa-study` package) and the downstream MD × BEDROC analysis live side by side in reading
order. See NB 01 for the research-question map.

- **Act 1 — setup (`00..06`).** Data catalog, scope map, MD/GBSA provenance, dataset overview,
  coverage, docking + GBSA baselines.
- **Act 2 — data-side experiments (`07..13`).** GBSA physics importance, DOE analysis, GROMACS
  screening, timestep stability + throughput, temporal convergence, selection correction.
- **Act 3 — MD features on discovery-9 (`14..21`).** Per-complex deep dive, per-target
  aggregation, feature distributions, kinematic phase space, time-series overlays, active-site
  fingerprints, feature correlations, actives-vs-decoys separation.
- **Act 4 — ranking + verdict (`22..30`).** BEDROC baselines, ML combo selection, full-factorial
  ML, deep-research verdict, GBSA-parameter vs MD, ligand-chem GBSA surrogate, single-feature
  BEDROC, rank fusion, family stratification.

Downstream analysis uses `src/discovery9/` (`paths`, `style`, `io`, `metrics`); the
upstream-origin NBs use `src/gbsabench/`. All notebooks write to a single `figures/` tree with
`NN_slug_figK.png` prefixes.

- **Entry-point notebook — `notebooks/01_scope_and_map.ipynb`.** NewBench-27 scope grid,
  MD/GBSA availability heatmap, research-question map.

## Reproducibility

Environment pinned via `env/pixi.toml` + `env/pixi.lock`.

```bash
# 1. install environment
cd env && pixi install

# 2. regenerate derived tables in dependency order
pixi run python ../reproduce/aggregate_results.py        # features.parquet
pixi run python ../reproduce/hardened_claim_b.py         # hardened_claim_b.csv
pixi run python ../reproduce/deep_research_wide.py       # deep_research_wide.csv
pixi run python ../reproduce/generate_summary_tables.py  # panel_bedroc_summary.csv, rank_fusion_sweep.csv

# 3. batch-execute every notebook in the flat tree (each writes its own figures at 300 dpi)
pixi run jupyter nbconvert --to notebook --execute --inplace \
    ../notebooks/*.ipynb
```

Upstream-origin NBs (02, 04–13) read from `data/external/gbsa-study/` and use `src/gbsabench/`.
Downstream-origin NBs (00, 01, 03, 14–30) read from `data/derived/` and use `src/discovery9/`.
NB `01_scope_and_map.ipynb` is the reader's entry point once you know the numbers.

`data/raw/complex_analyses/` holds the 270 per-complex outputs (one folder per
(target, complex_id), each with `summary.json` + 4 parquets + 2 TSVs). Regenerating those from
the raw GROMACS trajectories needs the upstream `data/external/gbsa-study` symlink and takes
~50 s / complex via `reproduce/analyze_complex.py`.
